# SPECTRA-32 v0.3.0: Chaos Lab

**Release date:** 2026-11-02

**Project:** VIGIL-IoT
**Release type:** feature release

## Summary

This release adds Chaos Lab, a separate, session-local behavioral simulator for studying how an ESP32-style IoT node model responds to bounded failure scenarios. It makes failure propagation, detection, recovery policy, and modeled service availability inspectable in the Streamlit UI.

## Included scenarios

- MQTT broker outage
- Wi-Fi connectivity loss
- Device / firmware crash
- Sensor failure
- Network latency
- Packet loss (bounded 0–50% parameter)
- Memory pressure
- Watchdog / task stall

Each scenario advances over a deterministic ten-second logical timeline. The UI can run the Vulnerable profile, the Hardened profile, or both against the same inputs. It shows the affected logical board path, node state, service-availability chart, recovery metrics, and event timeline. See [Chaos Lab model and metric definitions](../CHAOS_LAB.md) and the [EXP-02 protocol](../../experiments/EXP-02-chaos-resilience/README.md).

## Verification

The release is gated on the Python quality matrix, dependency audit, loopback MQTT integration job, and ESP-IDF 6.1 classic `esp32` build passing for the tagged source. The attached `release-manifest.json` identifies the source commit and exact workflow run IDs; `SHA256SUMS.txt` covers every release asset.

Local verification includes the full unittest suite, correctness-focused Ruff checks, Python compilation, documentation-link validation, dependency audit, and a live Streamlit run through a complete MQTT outage comparison. The local Mosquitto integration test is skipped when the broker is unavailable.

## Scope and limitations

The Vulnerable and Hardened profiles are declarative model policies, not separate verified firmware images. No process, radio, network, broker, serial port, firmware, GPIO, or physical sensor is touched. Availability, operation results, recovery time, retries, and the score are modeled outputs; no hardware measurement or empirical resilience result is included. Netflix Chaos Monkey is a high-level conceptual reference only; this project is not affiliated with Netflix and reuses no source code.

The Python runtime SBOM and ESP-IDF Component Manager lock are attached separately. The lock is not a complete firmware SBOM and does not include built-in ESP-IDF components or compiler/toolchain binaries.
